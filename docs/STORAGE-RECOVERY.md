# 应用索引与历史档案的备份、恢复

当前作品索引为 schema5，会话学习数据库为 schema2，备份容器格式仍为 1。本文按只读引用模式修订；阶段2报告中的复制档案流程仅是历史证据。

阶段6备份同时保存私有通用偏好台账和自动请求计数。恢复后自动学习、自动总结、远程发送、共享、原件路径和逐项目参与全部关闭；偏好文本保留，确认状态失效。恢复较旧备份不会降低当前同日请求计数或缩短冷却时间。备份不包含 API Key，也不访问被引用的原件。

## 引用索引不能替代项目备份

阶段5引用的备份只保存应用索引与应用自有状态，不读取、复制或备份被引用的原文件。数据库可能包含原始路径、校验、提取片段、来源状态和任务记录；应用自有人工上下文、删除标记、作用域设置及已脱敏的模型地址/名称也属于应用数据。因此备份仍可能包含敏感路径和正文片段，并非无敏感内容的纯目录列表。

恢复应用数据不会在项目中创建、写回、覆盖、移动或删除原文件，也不会把缺失原件从缓存恢复。用户应另用自己的项目/源码备份方案保护原件；Amifolio 的引用记录不能承担这项职责。

阶段9将旧 `objects`、`context-state`、`preference-state`、`recovery` 和旧投影同卷迁入 `history/legacy-随机编号`，同时保留一致的旧索引快照；不会重新读取项目原件生成副本。迁移日志支持中断恢复，旧进程重新创建资料时停止并保留两侧内容。当前引用索引、目录缓存、AI配置和会话学习台账保留。历史及其备份属于私人资料。

## 当前维护入口

默认产品桥接拒绝旧 `backup`、`restore` 和 `repo` 命令，不能沿用阶段2 CLI 示例把任意输出路径开放给 Agent。当前桌面也未承诺一键备份/恢复界面。底层 `PortfolioMaintenance` 兼容能力与测试仍保留，但不能把内部 API 存在写成已经提供并验收了用户入口；正式交付前须核对明确的维护方式和恢复演练结果。

维护者执行兼容维护时，应明确应用数据根（默认 `%LOCALAPPDATA%\Amifolio`），并遵循以下边界：

- 运行中备份需捕获 SQLite 一致快照和对应应用自有状态，不能直接复制正在使用的数据库就声称完整。新引用只备索引，不打开项目原路径补齐文件。
- 目标在应用库之外，使用新名称，不覆盖同名备份；临时文件不报告成功。每个归档条目有 SHA-256 清单；格式上限为 32 GiB、100,000 个文件，超限明确失败。
- 不包含 API Key、正式宿主配置、已安装 skill 或当前共享投影。阶段9备份包含安全检查后的只读历史及迁移版本标记；历史快照采用一致数据库副本，排除凭据文件和数据库临时旁文件。备份不自动加密，另行妥善保管。
- 恢复前关闭使用目标库的桌面和 MCP。先在同级临时目录核验路径、清单、哈希和数据库版本，再交换应用库；拒绝链接、越界、重复路径、未知格式和损坏数据。
- 原件已不存在不等于引用索引损坏：恢复不能要求补出项目文件。遗留历史实体则按其兼容完整性规则校验，不能混淆两类数据。

维护者不应借恢复操作修改真实 Codex 配置、密钥、项目原件或权限。配置恢复与 AGENTS/skill 安装仍是单独的明确配置操作。

## 恢复后的状态

引用记录恢复后清空旧校验与预览、标为未解析，旧未完成引用提取任务取消。重新发现当前有效 Codex 项目、核对实际原路径后，由用户显式选择解析；不自动重建源文件或把旧片段变成当前原文。来源移动、变化、缺失、不可读或当前不再属于发现范围时，须报告失效。

恢复后继续遵守新鲜度边界：扫描只检查 size/mtime，不逐文件哈希；选择已解析文件详情时才重算 SHA-256。上下文依赖元数据失效与已有片段，不实时监视源文件，也不保证每次共享都识别同 size/mtime 的内容变化；需通过详情核验或显式重新解析确认。

共享、原件路径与远程发送关闭；旧自动收纳授权禁用，不能重新启动复制流程。候选及自动派生总结失效，人工记忆、文档删除标记、模型地址/名称保留；密钥需重新填写保存。核对后由用户分别开启需要的作用域和许可。恢复旧备份可能重新带回应用当时的记录或人工文档，不能宣称跨备份永久遗忘。

被替换的旧应用库保存在同级 `原目录.before-restore-随机编号`，不自动清除。交换中断时保留恢复日志并补完或回退；提示日志损坏时应保留旧库与恢复点排查，不能静默重建空库。旧目录可能含原设置和加密凭据，仍需私人保管。

## 升级、删除与回收

升级前在应用库内保留数据库迁移恢复点；schema4 增加原路径引用，不自动把历史副本迁入原目录。不支持的未来版本或损坏数据库应明确失败。迁移恢复点仅用于数据库排查，不能替代应用数据或用户项目的独立备份。

schema5 只为应用已有元数据与提取片段建立搜索和目录索引，不读取原件补齐正文。已停用旧链路的数据库恢复点存入 `index-recovery`，不重新创建已退休的旧 `recovery` 目录。会话学习升级前保留 `learning/schema-v1-recovery.sqlite`；不覆盖已有恢复点。

学习正文分为常用和历史区。常用区最多10000条概述、2000条画像；已处理概述、未启用的自动画像可分批转入历史，永久身份、修订、删除保护及来源关系保留。活跃或人工画像、仍待处理或可重试回合不会为腾空间被静默删除。历史记录可分页查看、恢复或删除；恢复沿用原状态和授权，不自动启用共享。永久保护账本和历史正文仍会增长，这不是无限容量承诺。

当前只读产品没有“删除项目原件”或作品元数据编辑入口。应用自己的概要、记忆、风格、总结与设置可编辑、关闭或删除；相关候选、自动投影和迟到任务需遵守撤回。人工保留内容应由用户核对，外部程序读走、导出、远程服务或独立备份中的内容无法自动追回。

兼容回收仅面向应用自己的历史对象存储，默认保留已移除历史副本 30 天，不是项目清理工具。有效引用、原始来源、未知文件名和正在使用的对象不得被回收；不存在后台自动删除源文件任务。没有本轮需要时不必为迁移主动回收旧档案。应用锁文件正常保留，不代表有常驻扫描服务。

## AI 配置

保存 AI 服务地址、模型与 API Key 只修改应用自己的设置；密钥由当前 Windows 用户 DPAPI 加密，不进入普通备份。保存本身不发送资料，生成仍需对应作用域许可、远程发送许可和用户操作。“清除保存”移除应用保存配置并关闭发送许可。

DPAPI 不保证换电脑/用户可解密，也不防御同一登录用户权限下的恶意程序；读取损坏时应提示重新填写，不静默覆盖。任务与启动边界见[任务说明](TASKS.md)。
