# Codex 项目扫描、只读解析与接入

本文按[阶段5设计](superpowers/specs/2026-11-13-amifolio-stage5-design.md)修订；本轮本地实现与对应自动化验收见[阶段5记录](releases/2026-11-13-stage5.md)。阶段4的“整理、收纳、授权输出目录”是历史流程，不能作为当前操作指南。当前项目只来自本机 Codex 发现结果，不提供上传、手动创建项目或任意文件/目录选择器来扩展范围。

## 从扫描到解析

1. 在作品页选择扫描 Codex 项目，核对项目卡片、实际目录及发现警告；项目页也只显示这些真实目录。
2. 点击项目进入原目录，逐层打开文件夹，使用面包屑、返回上级与刷新。按真实直接子目录展示，不按类型重排目录，也不靠“全部项目”下拉切换。
3. 当前目录过滤只作用于本层。若展示跨目录结果，必须带相对路径以区分同名文件。扫描读取目录元数据，不读取正文、不计算全文件内容、不复制、不自动解析。
4. 选择需要的普通文件，点击“解析所选文件”。提交时重新核对当前项目范围、路径、链接、排除项与限制；工作进程直接打开原路径只读句柄，应用自己的库保存校验、状态和有界预览。
5. 在详情核对状态及来源定位，再决定是否使用应用上下文。检测到源文件变化、移动、缺失、不可读或项目不再可用后，旧提取失效；没有自动恢复原文件的操作。

应用没有修改文件名、标签、项目归属等作品元数据，或复制、快照、改名、移动、删除项目原件的入口。项目文件字节、属性、权限和写入时间不得因扫描/解析被修改。目录内文件应称为“项目文件”；会话 cwd 不证明某个文件由 Codex 生成或在某次会话中被修改。

## 只读浏览快捷操作

| 操作 | 快捷方式 |
|---|---|
| 返回 / 前进 | 鼠标侧键、Alt+左 / 右、工具栏 |
| 上级目录 | Alt+上、上级按钮 |
| 刷新当前目录 | F5 |
| 全选 / 多选 | Ctrl+A、Ctrl或Shift选择 |
| 复制所选路径 | Ctrl+C、右键菜单 |
| 打开所选文件夹 | Enter或双击；普通文件不直接执行 |

快捷键仅在作品浏览生效，输入框保留编辑行为。排序先显示目录，再按名称、类型、修改时间或大小排列；项目卡片使用统一尺寸。失效、排除或不再发现的历史位置会被跳过，刷新可回到最近有效上级。

## 新鲜度与及时性

目录扫描只看大小/修改时间（size/mtime），不逐文件哈希或读取正文。选择已解析文件详情时才重算 SHA-256，检测同大小、同修改时间的内容改写；这次校验会读取该文件字节，不等于重新提取全文。

明确预览或生成候选时，会对本次最多24个片段来源校验内容，模型返回后再次核对，阻止同大小、同时间戳改写后的旧内容成为候选。普通上下文读取仍以元数据检查和已有片段为准，不每次全量重算所有来源哈希，也没有实时监视。因此不能宣传上下文与原件持续逐字同步；重要内容应查看来源详情并按需重新解析。

## 发现范围与限制

发现遵循进程有效 `CODEX_HOME`，未设置时使用当前用户的 `.codex`；只读取必要的有界项目元数据与会话头部，不读取对话正文、`auth.json` 或秘密目录，不启动宿主服务修复数据。局部元数据适配不是官方稳定协议，也不承诺完整复现官方侧栏；使用会话目录回退时需标明来源和不完整性。

目录必须在当前已发现的真实本机项目内。不存在、不可读、链接/目录联接、配置/凭据、缓存、构建目录及应用库等均需排除或报告；排除规则不能识别所有正文秘密。发现与逐层目录枚举有数量、时间和读取上限，达到限制需显示不完整，不能默默当作全项目完整清单。没有常驻目录监控、自动 OCR 或会话文件修改追踪。

文本 PDF、Office、文本/代码的页、段落、工作表/单元格、幻灯片和行号来源及上限见[格式说明](FORMATS.md)。扫描成功、引用登记、解析任务完成、正文可用是不同状态；不支持/损坏/加密/超限均应保留真实原因，不编造提取结果。

## 明确配置 Codex

在“Agent 接入”先查看实际配置路径与变更预览，再明确选择追加 MCP、安装 skill 或保存必要 AGENTS.md 托管入口。保留无关配置、用户规则、编码和换行；已有冲突不静默覆盖，保存前备份，外部修改须阻止覆盖。首次启动、项目扫描、引用登记不授权这些写入，也不会替用户重启或信任宿主钩子。

这些配置文件/skill 是只读项目规则的明确配置例外，不能借此修改其他项目原件。应用自己的设置、索引及记忆也可管理，但不会扩大原件写权限。Codex 元数据目录与 skill 安装目录不是同一个概念；实际安装路径以接入预览和宿主设置为准。

桌面与桥接必须使用一致的应用数据根和 `CODEX_HOME`。默认 CLI/MCP 的 `submit` 只登记发现范围内的一个文件引用，返回 `referenced`；不是上传、复制、备份或解析回执。桥接不提供项目创建、作品修改、原件删除或自动解析入口；重试/处理须回到应用明确操作。源码中的安装、工具输入输出及移除说明见 `plugins/codex/README.md`；运行包中请查看 `codex/README.md`。

## 结束钩子与历史档案

明确安装并由用户在 Codex 信任的结束钩子，每次只有限刷新项目发现及既有引用的状态/索引元数据。不扫描授权输出目录、不登记未选择的文件、不读取对话正文、不复制、不解析、不调用模型，也不常驻监控。旧输出目录收纳授权不再作为复制许可。钩子安静结束不能当成所有产物已登记或解析的证明；真实宿主调度仍须单独验收。

历史库、归档副本和兼容维护能力保留，不自动复制迁移或删除；默认目录浏览不展示旧档案为当前项目文件。Schema4 引用索引不负责备份原文件，详见[恢复说明](STORAGE-RECOVERY.md)。

## 应用自己的风格与记忆

概要、记忆、风格、总结可在对应全局/项目作用域查看、编辑、保存、取消、关闭和删除；来源和入口由系统维护。这里编辑的是应用自己的上下文，不是原项目文件。开启共享、允许原件路径与允许远程发送分别控制，扫描或解析不自动开启任何一项。

手动生成需有效配置、适用作用域许可和明确操作；发送前查看实际片段。模型输出先作为候选，缺乏依据可以不返回；确认采用后保留派生来源，可停用或删除，编辑后改为人工文档须再次明确确认。自动候选、逐项目通用偏好和请求限额见[风格与记忆](CONTEXT.md)。人工记忆不会因扫描或自动生成被覆盖，应用自产上下文不再次学习。

关闭共享/删除记忆应撤回应用控制的入口与派生内容，并防止旧任务恢复；人工保留与外部已读副本的边界需如实提示。不能替 Agent、模型服务、独立备份或用户导出执行远程遗忘。
