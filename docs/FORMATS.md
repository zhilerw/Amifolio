# 只读格式提取与来源定位

阶段5按需打开已发现项目中的原路径，使用只读句柄解析；不复制原件，不在项目目录生成侧车文件，也不修改原文件字节、最后写入时间、属性或权限。来源路径、校验和、状态及有界预览由应用自己的索引保存。目录扫描本身不提取正文。原件变化后的过期判断属于引用索引流程，不能用旧缓存冒充当前内容。

## 支持范围

| 格式 | 内容与定位 | 明确边界 |
| --- | --- | --- |
| 文本 PDF | 按物理页顺序读取文本层，`[页 1]` 起算；支持 Unicode/ToUnicode 中文映射、常见 Flate 压缩文本 | 非版面复刻；复杂多栏、阅读顺序、字体映射及表格结构可能无法完整恢复。页码是物理页，不是印刷页码或 PDF 页标签 |
| 混合/扫描 PDF | 保留可读文本的原页码；存在无文本页时在状态提示需要 OCR | 未实现 OCR。空白页、纯图片页、文字为轮廓的页都可能没有文本；不声称仅凭空文本即可识别扫描件 |
| DOCX | 正文与表格中的段落，包含空段落计数；`[段落 n，表格单元格]`；保留制表符、显式换行 | 不提取页眉、页脚、批注、脚注或图片文本；段落不是 Word 渲染页码。读取已存字段结果，不运行字段/宏；删除修订不混入文本 |
| XLSX | 工作簿关系顺序的工作表、共享/内联富文本、实际单元格地址；`[工作表 名称，单元格 A3]` | 不加入拼音注音，不计算公式。公式只显示已有缓存；无缓存明确标为未计算。布尔值为 TRUE/FALSE。数值保持存储值，不推断日期、货币、百分比等显示样式；不追踪外部数据 |
| PPTX | 演示文稿关系顺序，`[幻灯片 n，段落 n]`；空白页保留编号位置，保留显式换行 | 不渲染，不提取图片/OCR、讲者备注、图表缓存或嵌入对象；不播放媒体/动画 |
| UTF-8、带 BOM 的 UTF-16/UTF-32 文本 | 文本、Markdown、代码、CSV/TSV，`[行 n]`；CR、LF、CRLF 均作为物理换行 | CSV/TSV 按文本行定位，非表格单元格语义；没有 BOM 的传统编码不猜测。二进制控制字符/无效 UTF-8 明确拒绝 |
| 脚本/代码 | 作为普通文本读取与定位 | 不执行脚本、宏、公式、文档内指令、JavaScript、链接或嵌入附件，不调用 Office/浏览器/外部阅读器 |
| 旧二进制 Office、ODF、RTF、图片等 | 可保留目录引用与格式分类 | 未实现正文提取；图片不自动 OCR。宏容器 DOCM/XLSM/PPTM 未接入 |

只索引最多 65,536 个 UTF-16 字符的预览（含定位标签与分隔符），不声称已经索引完整文档；到达上限明确显示“截断”。受损文件不会留下前几页/段落的成功预览。预览截断之后的页面未验证，文件后部损坏也可能尚未被触达。

## 状态与资源限制

- 加密 PDF，包括可用空密码打开的权限加密文件：明确“不支持提取：加密 PDF”；没有密码输入、猜测或解密入口。
- 损坏 PDF、缺失字体、错误 Office XML/单元格、无效编码：失败并返回空预览。PDF 可检测的非法字符映射单独标明，不能保证发现所有错误但看起来合法的字体映射。
- 空文档/空白或图片页：提示无可提取文本及可能需要 OCR，不冒充识别成功。PDF 压缩方式或结构不在受限支持范围时明确“不支持”。
- 独立解析工作进程沿用 Windows Job 限额：256 MiB 进程提交内存、1 个进程、25% CPU、30 秒期限；取消/超时/进程失败由任务层处理，可能无法给出更细的文件内部原因。这些限额不是所有合法文件均可解析的保证。
- PDF：输入最多 16 MiB，最多 256 页，递归深度 64；单页最多 100,000 字形（页解析后检查）。仅文本所需的 Flate、ASCII85、ASCIIHex 解码；单个编码/解码流最多 4 MiB，累计解码最多 16 MiB。Flate 在分配更多输出前检查限制；含 DecodeParms 的 Flate 预测器、LZW、RunLength 等暂不接入。图片不解码。未压缩流仍受输入与工作进程限制。
- Office：ZIP 最多 2,048 条目，单条目 8 MiB、展开总计/累计 XML 读取 32 MiB，超过 1 MiB 条目压缩比不得大于 200:1；拒绝路径穿越、重复名称、链接、DTD/外部实体。XML 深度 128、单部分 100,000 节点、累计 250,000 节点。关系只在 ZIP 内解析，不访问外部目标。

## PDF 组件与验证

使用固定版本 [PdfPig 0.1.16](https://www.nuget.org/packages/PdfPig/0.1.16)，纯托管 DLL，无可执行阅读器依赖；.NET 10 使用该包的 net9.0 资产，没有新增传递 NuGet 包。上游维护情况见 [0.1.16 发布记录](https://github.com/UglyToad/PdfPig/releases/tag/v0.1.16)，版本源码提交为 `a7bb35662bbbf405efddad50aedc9bcdcf515afc`。上游建议通过布局提取器读取页面文本，当前使用 `ContentOrderTextExtractor`，不直接拼接 PDF 内容流。详见 [第三方声明](../THIRD_PARTY_NOTICES.md) 和 [上游许可全文](third-party/PdfPig-0.1.16-LICENSE.txt)。

测试入口为 Core 测试程序的 `--filter format5`。夹具在一次性测试目录中构造真实交叉引用表、Type0/ToUnicode 中文多页 PDF、Flate 流、图片页和标准安全处理器 R2 加密 PDF，并验证正确密码能读回中文。Office 样本包括包内容类型/根关系、富文本、公式缓存、多页关系顺序和错误结构。测试比较原件 SHA-256、最后写入时间、只读属性及目录列表，另验证真实受限工作进程直接读取原路径。测试没有访问正式 Codex 配置、凭据或用户项目数据。
